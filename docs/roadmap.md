  新しい機能もこの原則の中で作る。

## 決めたこと（と理由）

### 実際の API 応答をそのまま記録してテストに使わない

記録した応答は本人の睡眠・心拍（タグを入れれば気分）の生データで、git に入れると履歴から消せない。
「健康データを保存しない」原則とも矛盾し、リポジトリを人に見せた時点で一緒に漏れる。

代わりに:
- 実際の応答から**構造（キーと型）だけ**を取り出し、値は合成したテスト用データを作る。
- 本物の API との照合は、手元で実行して値を保存せず、形が合っているかだけを判定するスクリプトにする。

### COROS のデータはこのサーバーに取り込まない

COROS の認証情報もこのサーバーに持たせると、守る鍵が 2 つになり、1 か所破られれば両方漏れる。
脅威分析とテストの範囲も倍になる。COROS の API が個人向けに開放されているかも未確認（推測）。

代わりに:
- COROS は Claude の COROS コネクタのまま使う。
- このサーバーは出力の形（日付・指標名・単位）を揃えることに専念し、2 台の比較は Claude 側で行う。

### 分析ツールの条件

- **その都度計算し、結果を保存しない。** 普段の値を保存すると、保存しない原則が崩れる。
- **Oura がすでに出している「普段との差」を先に使う。** 回復度の内訳はすでに返している。
  作り直す前に、それで足りるかを試す。
- **結論を出させない。** データが数週間分のうちは、気分と HRV の関係は偶然とほぼ区別できない（可能性が高い）。
  ツールは「外れ値」と「何日分のデータに基づくか」を返す。

### タグは権限追加と脅威分析の更新をセットで行う

`tag` 権限を足すと最小権限の範囲が広がり、気分という最も機微なデータを扱うことになる。
